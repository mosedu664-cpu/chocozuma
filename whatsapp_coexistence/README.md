# WhatsApp Coexistence — extension of the native `whatsapp` module

Adds a **connection type** to `whatsapp.account`: *Cloud API (dedicated)* or
*Coexistence*. In Coexistence the number keeps being used on the phone while the
Cloud API observes (echoes) and sends alongside it. It reuses the **same Meta
app** (Tech Provider) — no second application, no second icon in Odoo.

Two editions share this source: `whatsapp_coexistence` (Odoo Enterprise's
`whatsapp`) and `rcstudio_whatsapp_coexistence` (RC Studio's Community
`rcstudio_whatsapp`), generated by `scripts/build_coexistence_community.py`.

## Setup

Everything is configured on the **WhatsApp account** (not in Settings).

1. Install the module (depends on `whatsapp` / `rcstudio_whatsapp`).
2. **WhatsApp → Configuration → WhatsApp Business Accounts**: create or open an
   account and set **Connection Type = Coexistence**.
3. Either enter the **App ID**, **App Secret** and **Login Configuration ID** of
   your own Meta (Tech Provider) app, or leave the App Secret empty and paste
   the **RC Studio license**. Phone Number ID / Account ID / Token are hidden in
   Coexistence: the onboarding fills them.
4. Save and click **Connect via Coexistence** → scan the QR code from the app
   (choose "existing account", NOT "new number").

> The Graph API version is a module constant (`v25.0`), overridable with the
> system parameter `whatsapp_coex.graph_version`.

> No callback URL or verify token to type: the native account generates them
> (`callback_url = <base_url>/whatsapp/webhook`, random `webhook_verify_token`)
> and the onboarding registers them on Meta as `override_callback_uri`.

## What the onboarding does (`/whatsapp/coexistence/exchange`)

1. Exchanges the Embedded Signup `code` for a System User token (never expires).
2. Fills the native account: `app_uid`, `account_uid` (WABA), `phone_uid`,
   `token`, `phone_number`, `connection_type=coexistence`.
3. `POST /{waba}/subscribed_apps` with `override_callback_uri` = the native
   `callback_url` and `verify_token` = the account's `webhook_verify_token`.
4. Skips `register` (not applicable to coexistence).
5. Reads the number's details and triggers the two syncs (contacts + history,
   24-hour window; non-fatal, retry from the account buttons).

## Messaging

- **Inbound**: handled by the **native webhook** (account matched by
  `account_uid` + `phone_uid`) → regular Discuss channel.
- **Phone echoes** (`smb_message_echoes` → `message_echoes`, contact = `to`):
  the controller extends the native webhook and grafts them as **outbound**
  messages in the same channel, deduplicated by `whatsapp_inbound_msg_uid`.
- **Chat history** (`history`, sent once after the onboarding, in chunks): one
  thread per customer. Each message is written straight into that customer's
  Discuss channel with its original date (inbound if `from` is the customer,
  outbound otherwise), deduplicated by wamid. It does not go through
  `message_post`, so old messages neither notify the team nor reopen the
  24-hour window, and they are marked as read for members who were up to date
  (a member with unread messages keeps them). Media comes first as a
  `media_placeholder`; for the last ~2 weeks Meta then sends a second `history`
  webhook with a top-level `messages` array (or `message_echoes`, `to` = the
  customer, for what the business sent) and the same wamid, which attaches
  the file to the message already imported (or imports it, if it comes first).
  Older media is never sent. Media past a per-request time budget stays a
  placeholder. Button replies, reactions and unsupported messages are shown as
  text. Each chunk logs its phase, order and progress. Discuss orders by id,
  not by date: history landing in a channel that already has messages shows
  after them, and Meta does not deliver the chunks in order, so a recent chunk
  may land before an older one. Each message keeps its real date.
- **Sending / templates**: the native module's.

## Coexistence limits

- Messages typed on the phone go out raw; they only arrive afterwards as echoes
  (they cannot be intercepted or rewritten).
- Initial sync: once per number, 24-hour window. `(#4) Application request
  limit reached` is a temporary app rate limit; retry later.
- The number must have been active on WhatsApp Business for 7 days or more.
